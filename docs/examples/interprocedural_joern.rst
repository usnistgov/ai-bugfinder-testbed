5. Interprocedural - Joern 2.0
------------------
In the version 2.0.xxx and above, Joern supports interprocedural data-flow across
procedure and file boundaries. This feature is accessible by what they call data-flow
query steps.

The bugfinder includes a wrapper for the ``joern-cli`` which allows a script call to
execute those data-flow steps. The interprocedural analysis then needs to be made
entirely on Scala, using the CPGQL (Code Property Graph Query Language) directives
described in the Joern's documentation. Even though is possible to use the bugfinder
to execute the analysis, it's recommended to only generate the CPGs using the tool
and then ingest those CPGs into Joern via the command-line interface. That way, the 
user is able to traverse the graph to have a better idea of which nodes can be used 
as sources and sinks.

This section includes an example on how the interprocedural analysis can be executed.

5.1. Generating the Code Property Graph
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
To illustrate this section, consider the following code, which will be called
``example.c``:

.. code:: c

    #include <stdio.h>
    #include <stdlib.h>

    int getNumber() {
        int number = atoi("8");
        number = number + 10;
        return number;
    }

    void *scenario1(int x) {
        void *p = malloc(x);
        return p;
    }

    void *scenario2(int y) {
        int z = 10;
        void *p = malloc(y * z);
        return p;
    }

    void *scenario3() {
        int a = getNumber();
        void *p = malloc(a);
        return p;
    }

To generate the Code Property Graph, it's necessary to use the ``new_joern.py`` script.
Sonce only the Code Property Graph parsing is necessary for the analysis, only the
``cpg`` step is necessary, which will generate the CPG in a binary format. Run:

.. code:: bash

    python ./scripts/run_new_joern.py example.c cpg \
        --language $LANGUAGE


5.2. Analyzing the Code Property Graph
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
After generating the Code Property Graph, it's time to check the data-flows between
functions. There's two ways to do this: ingesting the generated CPG directly into
Joern using the command-line interface, or writing a script in Scala and executing it
either directly on Joern, or using the tool's wrapper.

In this example, each of these steps can be executed in ``joern`` command-line
interface. To start, run:

.. code-block:: bash

    $PATH_TO_JOERN_CLI/joern $PATH_TO_CPG

Where ``$PATH_TO_CPG`` is the binary file generated by step 5.1. ``joern`` then will 
process the CPG and open an interface where you can traverse the graph.

In this case, the query will look for all parameters for all functions to
an argument of ``malloc``:

.. code-block:: bash

    def source = cpg.method.parameter
    def sink = cpg.method.call.name("malloc").argument

    sink.reachableBy(source).flows.p

Those two lines of code define the sources and sinks to be analyzed. As a source, 
this definition will return for all parameters for all functions: ``cpg`` is the root
node of the CPG, ``method`` returns all nodes of ``METHOD`` type and ``parameter``
returns all nodes of ``METHOD_PARAMETER_IN`` type. And the sink is defined as the
argument of ``malloc`` at all ``malloc`` call sites. The next query prints all
reachable flows between the sources and the sinks:

.. code-block:: bash

    val res7: List[String] = List(
    """___________________________________________________________________________
    | nodeType          | tracked          | lineNumber| method    | file      |
    |==========================================================================|
    | MethodParameterIn | scenario1(int x) | 10        | scenario1 | example.c |
    | Identifier        | malloc(x)        | 11        | scenario1 | example.c |
    """,
    """___________________________________________________________________________
    | nodeType          | tracked          | lineNumber| method    | file      |
    |==========================================================================|
    | MethodParameterIn | scenario2(int y) | 15        | scenario2 | example.c |
    | Identifier        | y * z            | 17        | scenario2 | example.c |
    | Call              | y * z            | 17        | scenario2 | example.c |
    """
    )

Since the ``scenario3`` function doesn't have any parameters, the data-flow
analysis was not able to reach it. Let's change the ``source`` query to the
return of the ``atoi`` function and run the analysis again:

.. code-block:: bash

    def source = cpg.method.name("atoi").methodReturn
    def sink = cpg.method.call.name("malloc").argument

    sink.reachableBy(source).p

.. code-block:: bash

    val res8: List[String] = List(
    """__________________________________________________________________________
    | nodeType     | tracked              | lineNumber| method    | file      |
    |=========================================================================|
    | MethodReturn | RET                  | N/A       | atoi      | <unknown> |
    | Call         | atoi("8")            | 5         | getNumber | example.c |
    | Identifier   | number = atoi("8")   | 5         | getNumber | example.c |
    | Call         | number + 10          | 6         | getNumber | example.c |
    | Identifier   | number = number + 10 | 6         | getNumber | example.c |
    | Identifier   | return number;       | 7         | getNumber | example.c |
    | Return       | return number;       | 7         | getNumber | example.c |
    | MethodReturn | RET                  | 4         | getNumber | example.c |
    | Call         | getNumber()          | 22        | scenario3 | example.c |
    | Identifier   | a = getNumber()      | 22        | scenario3 | example.c |
    | Identifier   | malloc(a)            | 23        | scenario3 | example.c |
    """
    )


5.3. Executing the analysis as an external script
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
As seen in the example, the main issue with the analysis is to determine which
nodes will be used as sources and sinks following the CPGQL syntax. If you have
your sources and sinks defined, you can run the analysis using the tool as an
external script, without having to use ``joern`` command-line interface.

Using the example above, we can use these steps as an Scala function, and save
it in a script called ``example.scala``:

.. code-block:: scala

    @main def main(code: String, output_file: String) = {
        importCpg(code)

        val source = cpg.method.parameter
        val sink = cpg.method.call.name("malloc").argument

        val result = sink.reachableByFlows(source)

        result.toJsonPretty #> output_file
    }

This script then can be executed by using the ``joern`` interface or the tool's
wrapper. To execute it with ``joern``:

.. code-block:: bash
    
    $PATH_TO_JOERN_CLI/joern --script=$SCRIPT_PATH \
        --param code=$CPG_BINARY_FILE --param output_file=$OUTPUT_FILE

The script's execution is done by the ``run_new_joern.py`` script. To do so, run:

.. code-block:: bash
    
    python ./scripts/run_new_joern.py script --params \
        code $CPG_BINARY_FILE output_file $OUTPUT_FILE
